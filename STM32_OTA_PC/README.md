# STM32G431 单分区上位机

图形界面采用 AT32 上位机的五步布局：串口连接、OTA 固件、协议设置、操作与测试、收发日志。合并工厂镜像和 SWD 烧录放在独立窗口。协议和镜像布局针对本项目 STM32G431RBTx，不能使用 AT32 的镜像或目标配置。

## 运行

需要 Python 3.8 及以上、Tkinter 和 pyserial：

```powershell
python -m pip install -r STM32_OTA_PC\requirements.txt
python STM32_OTA_PC\app.py
```

串口接 USART2（PA2 TX、PA3 RX，RS-485 方向控制 PA1，高电平发送、低电平接收），默认 1000000 波特、8N1。Bootloader、APP 的 OTA 管理及业务 Modbus、上位机统一使用站号 3（`0x03`）。设备有有效 APP 时会在上电后约 4 秒跳转；查询进入握手后保持在 Bootloader。

Bootloader 的设备端升级状态日志从独立 USART1 输出：PB6 TX、PB7 RX，115200、8N1。使用第二路 USB-TTL 接收 PB6 并共地；OTA 上位机仍连接 USART2 的 RS-485 端口。ASCII 日志不混入 OTA 协议，APP 启动后 Bootloader 日志结束。

## 镜像和升级

1. 在“串口升级固件”中选择输入类型：
   - **已打包 OTA 镜像**：在“OTA BIN”选择已有镜像。工具校验镜像的版本、APP 向量和 SHA-256，升级时按版本输入框更新 1 KiB 版本区，保留原摘要和 APP，不修改源文件。
   - **原始 APP（自动打包）**：在“原始 APP BIN”选择**链接到 `0x08004800` 的原始 APP**，并填写 UTF-8 版本。点击升级时工具在内存中加入版本和 SHA-256 后发送，不修改原文件，也不会自动生成文件。
2. 连接串口并查询，点击“开始 OTA”后在操作区核对串口、固件类型、文件和版本，再点击“确认执行”或“取消”。工具先查询、等待开始擦除确认，然后逐包等待对应 ACK，不会在超时后盲目重传。会话 Key 支持十进制或 `0x` 十六进制，每包数据支持 1～1024 字节，应答超时可设置；擦除确认至少等待 30 秒。字节序和首包号按当前固件固定。设备默认使用 8N1，其他校验和停止位须与设备配置一致。
3. 如需保存打包结果，可选择原始 APP、填写版本并点击“生成 OTA”；工具会保存镜像并切换为“已打包 OTA 镜像”。版本区占 1 KiB、零填充；随后 1 KiB 摘要区的前 32 字节为原始 APP 的 SHA-256，剩余补零。
4. 点击“合并 Bootloader + APP 烧录文件…”打开独立窗口，选择原始 APP BIN 和不超过 14 KiB 的 Bootloader BIN；可输出完整 128 KiB BIN 或 Intel HEX。BIN 含有效记录，空白填 `0xFF`。不能用工厂镜像作为 OTA 镜像。

操作区提供查询/无操作测试、离线协议自检、重启设备、重启并查询 OTA、查询版本号和持续压力测试。“手动回滚”只说明单分区不支持回滚，不发送回滚命令。升级显示已确认包数、字节数、耗时、平均速度、最近包确认耗时、收发量、当前阶段和最近接收摘要。界面保留最近最多约 5000 行、256 Ki 字符，单条长 HEX 仅显示约 1024 字符预览，可水平滚动；支持清空和导出当前显示日志。压测磁盘日志在截断显示之前记录完整明细，按下述分卷容量保留。

串口枚举、连接、接收、查询及关闭均在后台执行；界面不等待串口读取。日志分批刷新，进度及接收摘要只显示最新值，完成/错误通知不会被日志挤掉。普通升级或查询期间可点击“断开”中止等待；关闭普通串口操作会先中止并释放连接。压力测试仍采用“完成本轮后停止”，也可通过断开立即中止。中止正在进行的单分区升级后，需要重新完整升级。

## 版本查询和进入 OTA

两端固件均须更新到本次版本。APP 运行时，“查询 OTA 状态”返回禁止升级（0）；点击“重启并查询 OTA”，确认后工具等待重启应答，然后每隔 50 ms 以短超时查询 Bootloader，收到允许升级状态后提示就绪。此时可点击“开始 OTA”。APP 中的开始升级和回滚请求只返回禁止状态，不执行 Flash 操作。

“查询版本号”读取 `0x08004000` 的 OTA 版本区，并显示 Bootloader / APP 模式。它不读取 APP 的编译版本宏。自定义 `0x11` 请求为 `03 11 | offset u16 | count u16 | CRC16`，每块 1～32 字节，范围限于 1024 字节版本区；应答为 `03 11 | mode u8 | offset u16 | count u8 | data | CRC16`，mode 0 为 Bootloader、1 为 APP。字段大端，CRC16 低字节在前；上位机完整拼接后再解码 UTF-8。非法范围或 CRC 错误请求静默丢弃。

## 持续升级压力测试

1. 连接串口，选择已打包 OTA 或原始 APP，填写数字起始版本（例如 `1.0.1`），设置 APP 启动超时（默认 30 秒）和日志目录。
2. 点击“开始压力测试”并确认。固件在开始前读入一次，后续轮次使用同一快照；取起始版本和同段数设备数字版本中较大的值，末段加 1。每轮只更新版本区，摘要和 APP 保持不变。
3. APP 模式会自动重启进入 Bootloader，再握手、下载并等待 APP；只有 APP 模式且回读版本完全匹配才记为成功。版本不符、停在 Bootloader 或仅达到 100% 均不算成功。
4. 失败记录阶段和原因，等待 1 秒后开始新一轮完整升级，不盲目重传旧数据包。没有轮数上限。“停止（完成本轮）”和关闭窗口会等待当前轮结束；断开串口会中止当前操作。

擦除后确认丢失、版本区为空或损坏时，下一轮会回退到 OTA 状态查询。仅收到 Bootloader 可升级状态（`0x0001`、`0x0002` 或 `0x0055`）才允许跳过旧版本读取，按上次目标版本继续递增，并从开始命令及首包重新完整升级。设备仍在 APP、正在操作 Flash 或无应答时，不会直接擦写。

旧 APP 不支持 `0x11` 时不能完成闭环压测，应先通过 SWD 烧录本次完整工厂镜像，或让旧 APP 进入 Bootloader 后手动升级一次。

日志同时生成 `.log`（带毫秒时间戳的 HEX 明细）、`.commands.log`（查询、运行模式、版本、重启、升级及每轮结果，不记录固件 HEX）和 `.jsonl`（每轮目标/实际版本、耗时、结果及累计计数）。每条立即 flush。详细日志每卷 8 MiB，其他两类每卷 4 MiB，各保留当前卷及 3 个旧卷，本次最多 64 MiB；覆盖的仅是本次最旧分卷。已有测试历史加本次预算超过 512 MiB 时拒绝启动；磁盘剩余低于 256 MiB 或写入失败会停止压测。界面忙时可省略显示日志，磁盘记录仍保留在分卷预算内。

每包收到成功 ACK 后，日志单独记录该包进度：已确认包数、协议包号、百分比、累计字节数、本包大小和确认耗时。即使多个包对应相同的整数百分比，也会逐包记录；失败或超时的包不会计入已确认进度。

只有一个 APP 分区，开始升级即使旧 APP 失效并擦除，失败或断电后需重新完整升级，**没有回滚**。最后 ACK 表示设备已验证 SHA-256 和向量并写入有效记录，不代表 APP 已成功运行。SHA-256 是完整性检查，不是来源认证。状态主动上报与开始失败的状态帧无法可靠区分；开始时若先收到状态帧，工具会安全停止并要求重新查询。

## 通信日志

连接后，界面日志实时显示串口发送和接收的原始 HEX 字节、收发字节数、解析出的状态和应答，以及 CRC16 错误和异常。空闲时设备主动上报的信息也会显示；“清空日志”只清空显示内容，不发送命令。操作错误和升级结果显示在日志中，不使用提示弹窗；选择或保存文件仍使用系统文件选择窗口。

## SWD 工厂烧录

需要另行安装 pyOCD 和 STM32G431 设备包，并在“pyOCD”栏填写可执行文件路径或确保其在 PATH 中，例如：

```powershell
python -m pip install pyocd
pyocd pack install stm32g431rbtx
```

选择工具生成的完整工厂 BIN，枚举并手动选择下载器，核对实际芯片型号后在“操作确认”区域点击“确认执行”。工具检查芯片系列 DEV_ID `0x468` 和 128 KiB Flash，但这些信息不能单独区分所有同系列封装型号，仍需人工核实 STM32G431RBTx。烧录会擦写完整 128 KiB，随后读回逐字节比较；失败时不得将设备视为烧录成功。校验通过后可手动复位设备。请勿在不确认目标的情况下操作。

运行软件测试（不接触硬件）：

```powershell
python -m unittest discover -s STM32_OTA_PC -p "test*.py" -v
```
