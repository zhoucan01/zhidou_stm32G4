# 通信接口

## 产品控制口

| 项目 | 配置 |
|---|---|
| 协议 | Modbus RTU |
| 从站 | 3 |
| 串口 | USART2，PA2 TX、PA3 RX |
| RS485 方向 | PA4 `DE&~RE` |
| 参数 | 1,000,000 baud、8N1、无流控 |
| POWER V004 接口 | CN3 |
| F1_TEST 接口 | CN4 |

A1 上位机用于产品寄存器控制，但不能发送任意裸帧。地址 33 以后的工程功能使用：

```powershell
.\tools\product-modbus.cmd COM14
```

完整寄存器与命令见 [`F1_PRODUCT_MODBUS.md`](F1_PRODUCT_MODBUS.md)。同一个 COM 口不能同时被上位机和命令行工具打开。

## 其他串口

USART1 PB6/PB7 保持 `115200 baud、8N1`，仍由 MCSDK Monitor 协议占用，并不是产品 ASCII 命令口。USART3 PC10/PC11 也保持 `115200 baud、8N1`，但本板未确认外部连接，不属于产品控制接口。只有 USART2 的 RS485 产品口使用 `1,000,000 baud`。

收到合法 Modbus 回复只证明通信链路和固件解析器工作；电机、加热和功率输出必须结合状态回读与实测确认。

## F1_TEST 运行中丢帧记录

2026-09-29，F1_TEST v1.5 实验板在电机停止时能够通信，但开启电机 PWM 后绝大多数
Modbus 请求超时，偶尔仍有完整回复，而且与电机转速无明显关系。最终确认 USB-RS485
接口只连接了 A/B、没有连接 CN4 `DGND`；补接该参考地后问题消失。原理图显示该板使用
非隔离 U17 `SN65HVD3082EDR`，收发器直接参考功率控制侧 `DGND`。

遇到“停机通信正常、PWM 开启后大量超时”时，先检查 A、B 和信号地三根连接，再检查
终端电阻、线长和屏蔽。A/B 差分传输仍受收发器允许共模范围约束；不能把“不需要信号
参考地”作为默认接线方式。该故障不是未连接加热负载造成的，当时加热档位均为 0。

POWER V004 的情况不同：U28 `SM4500(H)` 将 MCU 的 `GND1` 与 CN3 总线侧 `GND` 隔离，
因此实测仅连接 P/N 也能运行，不能据此推断非隔离 F1_TEST 也可以省略参考地。POWER 板
在当前配置下两线可用属于隔离和具体布线条件下的结果，不是所有 RS485 系统的通用接法。
