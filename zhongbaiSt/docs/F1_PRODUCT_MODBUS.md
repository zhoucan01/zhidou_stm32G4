# F1 产品 Modbus 使用与协议说明

本文档是 `product-g4-modbus-m1` 分支的产品通信入口，适用于两个编译目标：

| 目标 | 板卡 | 固件 | RS485 | VBUS 采样 |
|---|---|---|---|---|
| `product-modbus` | v1.5 实验板 `F1_TEST` | `F1_Product_Modbus_v2_M1.hex` | CN4 | PA6 / ADC2_IN3 |
| `power-product-modbus` | `F1_POWER_V004` | `F1_POWER_V004_Product_Modbus_v2_M1.hex` | CN3 | PC2 / ADC2_IN8 |

两者使用相同的 M1 FOC、产品寄存器和工程扩展协议，但板级引脚不同，固件不能混刷。当前协议固件版本为 `0.2.7.0`。

## 1. 快速使用

通信参数：Modbus RTU，从站地址 `3`，`1,000,000 baud`，`8N1`，无流控。16 位寄存器在线上传输时高字节在前；CRC16 低字节在前。

随项目使用的上位机位于：

```text
C:\Users\Dimou\Downloads\A1-串口测试-26092301\debug\SerialAssistant.exe
```

上位机的操作顺序：

1. 选择实际 COM 口、`1,000,000`、协议 `2`、站号 `3`，然后打开串口。
2. 先打开“总开关”。总开关为 0 时，固件会清除电机档位和两个加热档位。
3. 电机档位写入 `-15..15`；0 停止，正数是 CW，负数是 CCW。对当前豆浆机定义，**CCW 是工作正方向**，因此工作方向使用负档位。
4. 加热使用“下加热”档位 `0..13`。`F1_POWER_V004` 只有 PB13/`HEAT` 这一路经过硬件确认。
5. 同时观察输入寄存器中的实际转速、MCSDK 状态、档位和加热状态，不要只看按钮状态。

档位绝对值和目标转速一一对应：1 = 1000 rpm，2 = 2000 rpm，依此类推，15 = 15000 rpm。产品档位固定使用 FAST、`RAMP_MS=500`、`ACC=32000 rpm/s`、`DEC=10000 rpm/s`、`IQRAW=10922`、速度 PI `200/25`，运行时间为连续。

方向切换不会直接反转。固件先停止，MCSDK 回到 IDLE 后再按新方向启动。1 档也会完成 FAST 强拖和观测器接管，然后闭环降到 1000 rpm。

## 2. 上位机能做什么

当前 A1 上位机能够完成标准产品控制和轮询：

- 写总开关、上下加热档位和有符号电机档位；
- 用 FC03 回读产品命令；
- 用 FC04 回读转速、状态、电流、档位和版本。

已确认这个上位机**没有可用的 Modbus 裸帧发送入口**。界面中的协议选择和滑块用于页面已有控件及其数值映射，并不能发送任意 RTU 帧。因此，地址 33 以后的工程扩展功能必须使用仓库里的 `tools/product-modbus.cmd`、其他 Modbus 主站软件，或自己写脚本。上位机与命令行工具不能同时占用同一个 COM 口。

## 3. 标准产品协议

### 3.1 支持的功能码

| 功能码 | 用途 | 地址范围 | 说明 |
|---:|---|---:|---|
| `0x01` | 读线圈 | 0..9 | 线圈 0 与总开关联动，其余仅保留 |
| `0x02` | 读离散输入 | 0..15 | 0..2 有定义 |
| `0x03` | 读保持寄存器 | 0..102 | 产品命令、工程参数和诊断量 |
| `0x04` | 读输入寄存器 | 0..13 | 上位机标准状态页 |
| `0x05` | 写单线圈 | 0..9 | 只有线圈 0 有控制意义 |
| `0x06` | 写单保持寄存器 | 0..102 | 单项设置 |
| `0x0F` | 写多线圈 | 0..9 | 一次写多个线圈 |
| `0x10` | 写多个保持寄存器 | 0..102 | 推荐用于成组提交参数 |

从站地址 0 是广播写入，固件执行但不回复。异常回复为功能码加 `0x80`：异常码 1 表示功能码非法，2 表示地址非法，3 表示数据非法。

本文全部地址均为 **Modbus PDU 的零基地址**。某些软件显示为 40001/30001 风格时，保持寄存器 0 对应 40001，输入寄存器 0 对应 30001。

### 3.2 产品写入：FC06 或 FC10

| 地址 | 数据 | 功能 | 建议回读 |
|---:|---:|---|---|
| 0 | 0/1 | 总开关；写 0 同时清除地址 2、3、4 | FC03 地址 0；FC04 地址 3 |
| 1 | 0..65535 | 上位机序号/保留字，固件不据此执行控制 | FC03 地址 1 |
| 2 | 0..13 | 下加热档位；0 关闭 | FC03 地址 2；FC04 地址 4、6 |
| 3 | 0..13 | 上加热档位 | FC03 地址 3；FC04 地址 5、7 |
| 4 | `int16` -15..15 | 有符号电机档位；正 CW，负 CCW，0 停止 | FC03 地址 4；FC04 地址 0、1、8 |
| 5 | 0/2/3/4 | 工程命令：0 无动作、2 立即停止、3 故障确认、4 按 DEC 减速停止 | FC03 地址 100 |

`F1_POWER_V004` 的 PB14 没有连接到第二路加热硬件，所以地址 3 即使被写入非零也会保持并回读为 0。该板只有地址 2 对应的 PB13/`HEAT` 有效。输入寄存器中的“加热状态”表示固件已接受命令并使能控制路径，不是功率、电流或温度反馈；硬件验证仍需测量 PB13、光耦/双向可控硅输出或实际功率。

一次提交总开关、上下加热和电机档位时，建议使用 FC10 从地址 0 连续写 5 个寄存器：

| 数据序号 | 地址 | 示例 | 含义 |
|---|---:|---:|---|
| 数据 1 | 0 | 1 | 总开关开 |
| 数据 2 | 1 | 1 | 序号/保留 |
| 数据 3 | 2 | 10 | 下加热 10 档 |
| 数据 4 | 3 | 0 | 上加热关 |
| 数据 5 | 4 | `0xFFF7` | -9，即 CCW 9000 rpm |

提交后先用 FC03 从地址 0 读取 5 个寄存器，确认固件实际保存的命令；再用 FC04 从地址 0 读取 14 个寄存器，确认运行状态。FC06/FC10 的正常写回复只表示帧被接受，不能单独证明电机或加热硬件已经动作。

### 3.3 标准状态回读：FC04

| 地址 | 含义 | 格式/单位 |
|---:|---|---|
| 0 | 电机实际转速 | 绝对值 rpm |
| 1 | MCSDK 电机状态 | `State_t` 数值 |
| 2 | 电机相电流幅值 | mA |
| 3 | 总开关状态 | 0/1 |
| 4 | 下加热命令状态 | 0/1 |
| 5 | 上加热命令状态 | 0/1；POWER 板恒为 0 |
| 6 | 下加热档位 | 0..13 |
| 7 | 上加热档位 | 0..13；POWER 板恒为 0 |
| 8 | 电机有符号档位 | `int16`，-15..15 |
| 9..10 | 保留 | 当前返回 0 |
| 11 | 版本高字 | 高字节 major，低字节 minor；当前 `0x0002` |
| 12 | 版本低字 | 高字节 patch，低字节 build；当前 `0x0400` |
| 13 | 保留 | 当前返回 0 |

固件上电后还会连续发送三次厂内版本帧：`76 major minor patch build CRC低 CRC高 6E`。这不是标准 Modbus 回复；主站打开端口后可先清空接收缓存，再开始轮询。正式版本判断以 FC04 地址 11、12 为准。

推荐的控制闭环：

1. FC06/FC10 写入命令。
2. FC03 回读对应保持寄存器，判断命令有没有被固件接受或被板级规则改写。
3. FC04 回读地址 0..13，判断 MCSDK 状态、实际转速和命令状态。
4. 加热还要以功率或波形测量确认；电机需要实际转速或可靠的观测器状态确认。

## 4. 上位机没有的工程功能

关闭 A1 上位机后，在 Windows 命令行运行：

```powershell
tools\product-modbus.cmd COM14
```

如果当前目录是 WSL：

```bash
cmd.exe /c "tools\product-modbus.cmd COM14"
```

缺少 pyserial 时执行：

```powershell
py -m pip install pyserial
```

交互模式常用命令：

```text
CFG
SET RAMP_MS 500
SET ACC 32000
SET DEC 10000
RUN -9000 MODE CL PROFILE FAST IQ 10922 RAMP 500 ACC 32000 DEC 10000 HOLD 60000
DIAG
WATCH 0.5
STOP
MOTOR -9
BAR 10
```

也可以非交互执行：

```powershell
tools\product-modbus.cmd COM14 --send "CFG" --send "RUN -9000 MODE CL PROFILE FAST IQ 10922 RAMP 500 ACC 32000 DEC 10000 HOLD 60000"
```

`RUN` 的 RPM 使用符号表示方向：正数 CW，负数 CCW。`HOLD 0` 表示连续运行；其他值允许 250..60000 ms。调参值只保存在 RAM，复位后恢复下表默认值。

命令行工具的 `BAR level` 只用 FC06 写地址 2，`MOTOR level` 只用 FC06 写地址 4；两者不会携带或重新提交另一通道的旧值。发生通信超时后可以安全地重发同一个 `BAR` 或 `MOTOR` 值。需要同时改变多个产品通道时才使用 `MISSION total bar roll motor`。

### 4.1 工程运行参数：FC03/FC06/FC10

| 地址 | 参数 | 有效范围 | 上电默认 | 搭配回读 |
|---:|---|---:|---:|---|
| 33 | Id Kp | `int16 > 0`，最终还受运动配置校验 | 3321 | FC03 33..38 |
| 34 | Id Ki | `int16 >= 0` | 122 | FC03 33..38 |
| 35 | Iq Kp | `int16 > 0` | 3321 | FC03 33..38 |
| 36 | Iq Ki | `int16 >= 0` | 122 | FC03 33..38 |
| 37 | 速度 Kp | `int16 > 0` | 200 | FC03 33..38 |
| 38 | 速度 Ki | `int16 >= 0` | 25 | FC03 33..38 |
| 40 | 模式 | 0=闭环，1=开环 | 0 | FC03 40..48 |
| 41 | 启动配置 | 0=STANDARD，1=FAST | 1 | FC03 40..48 |
| 42 | 有符号目标转速 | `int16`，非 0，绝对值不超过 20000 | 10000 | FC03 40..48 |
| 43 | IQRAW 限幅 | 200..10922 | 10922 | FC03 40..48 |
| 44 | 启动强拖时间 | 250..10000 ms | 500 | FC03 40..48 |
| 45 | 加速度 | 100..60000 rpm/s | 32000 | FC03 40..48 |
| 46 | 减速度 | 100..60000 rpm/s | 10000 | FC03 40..48 |
| 47 | 运行时间 | 0 或 250..60000 ms | 0 | FC03 40..48 |
| 48 | 执行命令 | 写 1 执行，随后自动清零 | 0 | FC03 48 + 状态寄存器 |

应先写 33..38 和 40..47，最后单独向地址 48 写 1；或者用一次 FC10 从地址 40 连续写 9 个数据，令最后一个数据为 1。执行回复只说明 Modbus 写入成功，是否起动必须继续读取地址 64..102 的状态快照。

### 4.2 工程状态快照：FC03 地址 64..102

`STATUS`、`DIAG` 和每次 `WATCH` 都只读取这一帧。标准上位机地址不变；17..27 和 50..59 只为旧工具兼容，新工具不再轮询它们。

| 地址 | 含义 | 格式 |
|---:|---|---|
| 64 | MCSDK 状态 | `State_t` 数值 |
| 65 | 综合状态位 | bit0 总开关；1 MOE；2/3 加热；4 RUN 请求；5 观测器有效；6 工程 RUN；7 Break 重试等待；8 BKIN；9 已使用重试 |
| 66 | 运行阶段 | 0 IDLE；1 START；2 HOLD；3 DECEL；4 BREAK_RETRY |
| 67..70 | 目标、参考、实际、观测器转速 | `int16` rpm |
| 71 | 母线电压 | V |
| 72 | 相电流幅值 | mA |
| 73..74 | 当前故障、历史故障 | MCSDK fault word |
| 75..78 | Id、Iq、IdRef、IqRef | `int16` raw |
| 79..82 | Vq/Vd 请求值、实际施加值 | `int16` raw |
| 83 | 运行报告位 | bit0 PWM；1 进入闭环；2 首次进带；3 参考到位；4 稳定到达 |
| 84..88 | PWM、闭环、进带、参考到位、稳定到达时间 | ms；`0xFFFF` 表示尚未发生 |
| 89 | 稳定到达时转速 | `int16` rpm |
| 90..91 | IQ 限幅累计时间 | `uint32`，低字在前 |
| 92..93 | 电压限幅累计次数 | `uint32`，低字在前 |
| 94..99 | CRC、非法帧、接收溢出计数 | 三个 `uint32`，各低字在前 |
| 100 | 最近工程命令结果 | 1 已接受；2 被拒绝 |
| 101 | 有符号电机档位 | `int16`，-15..15 |
| 102 | 最近停止原因 | 0 ACTIVE；1 NONE；2 COMMAND；3 TIMEOUT；4 FAULT；5 START_TIMEOUT；6 UNEXPECTED_STATE；7/8 RAMPSTOP；9..11 Break 重试失败 |

`STATUS` 显示日常运行量，`DIAG` 从同一帧显示电流、电压、时间及通信错误。连续监视使用 `WATCH 0.5`；启动后仍可输入 `DIAG`、`STOP`，使用 `WATCH OFF` 停止。前后台共享串口锁，不会交叉发送 RTU 帧。

### 4.3 产品 STOP 与故障恢复

上位机关闭总开关、把电机档位写为 0，或工程接口执行 `STOP` 时，固件都会先关闭 PWM 并取消运行请求。若实时故障已经消失，固件随后自动确认欠压、启动失败和速度反馈三类可恢复故障，因此上位机不需要单独提供 MCSDK `ACK` 控件。速度及观测器连续异常的容许次数由 3 次提高到 20 次（速度任务 1 kHz），用于滤除短暂失真；持续异常仍会停机。

以下故障不会由产品 STOP 自动确认：FOC 执行超时、母线过压、过温、BKIN/硬件过流以及软件内部错误。它们必须排除原因后通过工程接口明确执行 `ACK`。保护触发时 PWM 始终立即关闭，自动确认不会绕过实时保护。

MCU 复位时 IPM 故障输出与外部上拉可能尚未稳定，TIM1/BKIN2 因而可能锁存一次 `0x0040`。产品初始化完成后，仅当 PWM 从未打开、BKIN 已恢复高电平、当前故障为 0 且历史故障只有 `0x0040` 时，固件自动确认这次上电瞬态。初始化完成后的任何 BKIN 事件仍按硬件过流处理并保持锁存。

## 5. RTU 帧格式和示例

使用 FC06 写单寄存器：

```text
[站号 03] [功能码 06] [地址高] [地址低] [数据高] [数据低] [CRC低] [CRC高]
```

使用 FC10 写多个寄存器：

```text
[03] [10] [起始地址高低] [数量高低] [字节数] [数据1高低] [数据2高低] ... [CRC低高]
```

使用 FC03/FC04 读取：

```text
[03] [03或04] [起始地址高低] [数量高低] [CRC低高]
回复：[03] [功能码] [数据字节数] [数据1高低] [数据2高低] ... [CRC低高]
```

已校验的标准读取帧：

```text
03 03 00 00 00 05 84 2B   # FC03：读保持寄存器 0..4
03 04 00 00 00 0E 70 2C   # FC04：读输入寄存器 0..13
```

不建议手算 CRC；`tools/product_modbus.py` 会生成帧、验证回复长度和 CRC，并将有符号数据按补码解释。

## 6. 修改波特率

产品 Modbus 的固件波特率在 `Src/usart.c` 的 `MX_USART2_UART_Init()` 中：

```c
#if defined(F1_PRODUCT_MODBUS)
  huart2.Init.BaudRate = 1000000;
#else
  huart2.Init.BaudRate = 115200;
#endif
```

这项条件编译只改变 USART2 产品 RS485 口。USART1 的 MCSDK Monitor 和保留的 USART3 都继续使用 `115200 baud、8N1`。

修改后必须重新编译并烧录相应板卡固件，同时修改主站波特率：

```powershell
tools\product-modbus.cmd COM14 --baud 1000000
```

A1 上位机也必须选择或配置为同一波特率；如果页面不支持目标波特率，就不能继续使用它控制该固件。

产品构建通过 USART2 RX DMA 和 UART IDLE 事件接收完整数据块，并按功能码给出的请求长度拆帧；不再依赖 1 ms 分辨率的 `HAL_GetTick()` 静默时间。DMA 使用 DMA1 Channel 1、256 字节接收块，软件窗口为 2048 字节。发送回复时固件暂停接收、切换 RS485 方向，发送结束后立即重新启动 DMA 接收。

DMA 初始化受 `F1_PRODUCT_MODBUS` 构建宏控制，配置位于 `Src/usart.c`；公共 `.ioc`/`.ioc.wb` 同时服务非产品构建，因此没有把这一产品专用 DMA 通道写入 CubeMX 配置。若以后由 CubeMX 重新生成 `usart.c` 或中断文件，必须保留 USART2 RX 的 DMA1 Channel 1、DMAMUX1 时钟、UART IDLE 回调和 `DMA1_Channel1_IRQHandler`。

1 Mbaud 回归验证应覆盖 FC04 短读、FC03 长读、FC06 单寄存器写和 FC10 多寄存器写，并检查扩展快照内的 CRC、帧错误与 RX overflow 计数没有增加。2026-09-29 在 POWER V004 实验板上每类连续执行 50 次，共 200 次全部成功，三个计数增量均为 0。

## 7. 编译和烧录

F1_TEST 实验板：

```powershell
cmake --preset gcc-release
cmake --build --preset product-modbus
flash.cmd product
```

F1_POWER_V004：

```powershell
cmake --preset gcc-release
cmake --build --preset power-product-modbus
flash.cmd power-product
```

烧录前必须核对文件名和板卡。烧录成功只证明 MCU 中的镜像通过校验；仍需用 FC03/FC04 回读并实际验证电机和加热输出。
